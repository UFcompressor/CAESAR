# Compression and decompression API

The public API accepts the caller's tensor and returns a self-describing
`CompressionResult`. Shape conversion, spatial blocking, temporal padding, and
shape restoration are handled inside the library.

```cpp
#include <caesar/models/caesar_compress.h>
#include <caesar/models/caesar_decompress.h>

CompressionConfig config;
config.memory_data = field;  // Original tensor; no caller-side reshape/padding.
config.n_frame = 8;          // Required; only 8 is supported currently.
config.correction_method = caesar::CorrectionMethod::GAE;

Compressor compressor;
auto compressed = compressor.compress(config, 1e-4f);
Decompressor decompressor;
auto restored = decompressor.decompress(compressed);
```

GAE is the default correction method. `LBRC` and `NGLR` are alternatives;
`config.nglr_options` controls NGLR correction training. Requested relative error
bounds remain targets to validate on the actual data, not unconditional guarantees.
See [known limitations](TODO.txt) and [NGLR](nglr.md).

## Shapes and ownership

| Input | Output |
| --- | --- |
| `[T,H,W]` | `[T,H,W]` |
| `[S,T,H,W]` | `[S,T,H,W]` |
| `[V,S,T,H,W]` | `[1,S,T,H,W]`, containing variable index 0 only |

Singleton dimensions are retained. For 5D input, variables 1 through V−1 are not
encoded or reconstructed. `original_shape` retains the full caller shape;
`shape_info` describes the selected variable's restored shape and internal 5D
conversion. Spatial and temporal padding are recorded in `compressionMetaData`.
Noncontiguous tensors are accepted. Compression owns its working copy and does
not modify the caller's tensor.

Input must be a nonempty floating-point tensor with three through five dimensions.
The current pipeline computes and returns float32 data; CPU float64 input is
converted internally, so very small error targets may be limited by float32
precision. Double-precision input on MPS fails explicitly. Output resides on the
installed model's device. Transfer it with `.cpu()` if needed.

`n_frame` has no usable default: leaving it unset or setting it to anything other
than 8 throws. Compression and decompression use a fixed internal batch size of
128. The final partial batch uses only the samples present. NGLR's separate
training batch option does not change foundation-model inference batching.

## Model identity and lifetime

Constructors infer the device from the installed model. They optionally accept an
exact required model identity string, but no device or batch-size argument.
`CompressionResult` stores `model_id`, `n_frame`, correction method, original
shape, conversion metadata, encoded streams, and correction payloads.
Decompression checks that the installed model matches the result's identity
before decoding. It does not load a different checkpoint automatically.

Keep all three `.pt2` packages and all six `vbr_*` / `gs_*` probability tables
with the matching model installation. The result does not bundle model artifacts.
Use a separate compressor/decompressor object in each calling thread; the
existing per-thread model cache remains in use. See [models](models.md).

GPU-to-CPU portability is still pending: latent indexes are regenerated by the
hyper-decoder and are not yet serialized. This API change does not resolve or
validate that portability issue. ADIOS integration and its buffer format are
unchanged and still need migration to the new API.

## Saving complete results

```cpp
#include <caesar/models/serialization.h>

// Save every result field in one file, then reload and decompress.
caesar::save(compressed, "field.cae");
auto reloaded = caesar::load("field.cae");
auto restored_from_disk = decompressor.decompress(reloaded);

// Buffer API for ADIOS2 and other integrations.
auto bytes = caesar::serialize(compressed);
auto reloaded_from_buffer = caesar::deserialize(bytes.data(), bytes.size());
```

The version-1 buffer includes model identity, frame count, original shape,
all padding and compression metadata, both latent streams, and all GAE, LBRC,
and NGLR metadata and payloads (including NGLR weights). Embedded zero bytes
are preserved. The buffer has a magic number and version, uses little-endian
scalars and uint64 lengths, and currently requires 32-bit int and 64-bit size_t.
Readers reject unsupported versions, truncated data, invalid lengths, invalid
booleans/correction methods, and trailing bytes. This is a new format; it does
not read the old ADIOS2 field sequence or the CLI's three-file format.

`save` overwrites its destination. Model packages and probability tables are
still supplied separately by the matching installation. Serialization itself
requires no model loading or GPU execution and does not establish GPU-to-CPU
entropy-decoding portability.

In ADIOS2, replace the field-by-field writer with a length-prefixed buffer:

```cpp
auto bytes = caesar::serialize(comp);
WriteParameter(bufferOut, bufferOutOffset, uint64_t(bytes.size()));
std::memcpy(bufferOut + bufferOutOffset, bytes.data(), bytes.size());
bufferOutOffset += bytes.size();
```

On reading, validate that the length fits within the remaining input bytes,
then call `caesar::deserialize(bufferIn + bufferInOffset, length)` and advance
the offset. Pass the returned result to `Decompressor::decompress`. Bump the
ADIOS2 operator buffer version when switching formats; keep its outer shape,
data type, threshold handling, and per-variable slicing logic. See [the ADIOS2 migration notes](adios_serialization.md). The remote
ADIOS2 source must be updated separately.

## CLI migration

```sh
export CAESAR_MODEL_DIR="$PWD/exported_model"
build/CAESAR/caesar compress input.bin --shape 1,1,20,256,256 \
  --n-frame 8 --error-bound 0.001 --correction gae --output sample.cae
build/CAESAR/caesar decompress sample.cae --output restored.bin \
  --verify --original input.bin
```

The raw CLI input/output format is float32. Compression requires shape and
`--n-frame 8`. Decompression reads both from metadata; omit `--shape` and
`--n-frame`, including when verifying against the original file. The
`--batch-size`, `--compress-device`, and `--decompress-device` options have been
removed. Unknown options fail explicitly. Constant data may produce valid empty
`.latents` and `.hyper` files.

The CLI still writes three files: `.latents`, `.hyper`, and `.meta`. Metadata now
starts with the `CAESAPI1` header carrying model identity, frame count, and shape
information. Older metadata is rejected with a recompression message; this is a
format break. These files retain the existing native binary payload encoding and
are not a new portable serialization API. The C/D file-based tests also use the
new header. ADIOS migration to the buffer API above remains a separate integration task.
