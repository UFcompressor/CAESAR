# Repository Guidelines

## Project Structure & Module Organization

`CAESAR/` contains the C++17 compression library; `pyCAESAR/` contains Python model and training code. Root scripts handle the CLI, model registry, and AOTI export. Put checks in `tests/`, examples in `examples/`, and model documentation in `docs/`.

## Build, Test, and Development Commands

Install dependencies using the platform steps in `README.md`. From the repository root:

```bash
python3 model_registry.py --list          # List registered models
python3 compile_model.py cpu             # Export a selected checkpoint for CPU
cmake -S . -B build -DCMAKE_PREFIX_PATH="$(python3 -c 'import torch; print(torch.utils.cmake_prefix_path)')" -DBUILD_TESTS=ON
cmake --build build -j6                   # Build library and test binaries
python3 -m unittest discover -s tests -p 'test_model_registry.py' -v
```

Run relevant C++ binaries such as `build/tests/test_padding`. Local verification is CPU-only; do not claim GPU or cross-platform testing.

## Coding Style & Naming Conventions

Use C++17 and follow nearby two-space C++ indentation. Python uses four spaces and `snake_case` for modules and functions. The `dev/` tools format touched files: `dev/C++_format.sh path/to/file.cpp` uses clang-format; `dev/python_format.sh path/to/file.py` uses Black. CI checks both formatters. Avoid formatting unrelated files.

## Testing Guidelines

Add `test_*.cpp` or `test_*.py` files under `tests/`; register C++ targets in `tests/CMakeLists.txt`. Run affected CPU tests and report tests needing a compiled model, GPU, or another platform. No coverage threshold is configured. Consult `docs/TODO.txt` for current limitations and planned work.

## Commit & Pull Request Guidelines

Always create a new branch for each task. Never run `git push`; leave publishing to the maintainer. Recent commits use short, specific subjects, often ending in a pull request number such as `(#158)`. Pull requests should describe behavior, link related issues, and list CPU tests run and untested environments. Include sample commands for CLI changes.

## Model Artifacts & Integration

`/home/eklasky/Programs/UFL_MODELS` is the current local checkpoint repository and catalog source; `model_catalog.json` is CAESAR's synchronized snapshot. Evaluate Hugging Face or another higher-capacity host as a future storage option; do not assume migration is complete. Python exports the network as three AOTI packages (`.pt2`); C++ loads them at runtime. Keep all six `vbr_*` and `gs_*` `.bin` probability tables with each compiled installation. Latent indexes are generated by the hyper-decoder and must stay compatible with those tables so GPU compression can be decoded on CPU. `ModelCache` caches AOTI runners and probability tables by model identity per thread; metadata is initialized once per process. ADIOS integration is being changed: preserve compressed-buffer metadata and follow the model identity contract in `docs/models.md` when modifying that path.
